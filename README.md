# Аналитический агент по новостям компаний
Проект помогает руководителю быстро понять, как новость может повлиять на конкретную компанию.

Система:
1. Берёт профиль компании.
2. Получает новость.
3. Ищет подходящие фрагменты аналитики Альфа-Банка.
4. Отправляет профиль, новость и найденные фрагменты в разрешённую LLM.
5. Возвращает структурированный анализ: факты, влияние, риски, возможности, действия и источники.

## Основные возможности
- Профили компаний с полями: `industry`, `revenue`, `region`, `employees`, `products`, `profile_text`.
- Если сведений нет, значение равно `"неизвестно"`.
- Разделение PDF-документов Альфа-Банка на фрагменты.
- Для каждого фрагмента сохраняются название, текст, страница, источник и ссылка.
- Если фрагмент продолжается на нескольких страницах, сохраняются все страницы.
- Поиск 5 наиболее релевантных фрагментов по новости и профилю компании.
- Обработка новостей: уникальный номер, удаление дубликатов, объединение похожих новостей.
- Оценка соответствия новости профилю компании.
- Отправка запроса в разрешённую LLM и обработка ошибок API.

## Принципы работы с данными
- Система не выдумывает факты.
- Если данных недостаточно, модель должна прямо об этом сообщить.
- В ответе разделяются факты из аналитики Альфа-Банка и оценки AI.
- Каждый вывод сопровождается источником и номерами страниц.
- Предположения помечаются как неопределённость.

## Архитектура
```
новости (parser.py) ──► news.json ──► отбор под компанию (alfa_rag.select_company_news)
                                                │
профиль компании (alfa_rag.get_company_profile) ┤
                                                ▼
аналитика банка (seed_chunks.json) ──► поиск фрагментов (alfa_rag.search_bank_analytics)
                                                │
                                                ▼
                       pipeline.py: собирает контекст (профиль + новость + фрагменты)
                                                │
                                                ▼
                       llm_client.py: промпт ──► разрешённая LLM ──► JSON-ответ
                                                │
                                                ▼
                       проверка ответа: поля, выдуманные источники, числа ──► результат
```

| Файл | Назначение |
|------|-----------|
| `parser.py` | сбор новостей из RSS, дубликаты, объединение похожих, оценки |
| `alfa_rag.py` | профили компаний, фрагменты аналитики, поиск, отбор новостей |
| `llm_client.py` | запрос к LLM, таймаут и повторы, промпт, проверка ответа |
| `pipeline.py` | связывает все части: `analyze_for_company`, `answer_question` |
| `api_routes.py` | адреса FastAPI: `/api/companies`, `/api/feed`, `/api/analyze`, `/api/ask` |
| `audit_log.py` | журнал действий ИИ (`logs/audit.jsonl`), список разрешённых инструментов, маскирование ключа |
| `test_pipeline.py` | быстрая проверка на одной новости (с реальной моделью) |
| `tests/` | автоматические тесты без интернета и ключа |
| `Dockerfile` | сборка и запуск в контейнере |
| `requirements.txt`, `requirements.lock.txt` | зависимости и их точные версии |
| `THIRD_PARTY_NOTICES` | лицензии сторонних компонентов |

## Требования к окружению
- Python 3.10+
- Библиотеки из `requirements.txt` (`pip install -r requirements.txt`)
- Ключ доступа к API разрешённых моделей

## Агентная логика
Анализ выполняется как последовательность шагов (`pipeline.analyze_for_company`):
1. **План**: профиль компании, поиск аналитики, повторный поиск при нехватке данных, анализ, самопроверка.
2. **Инструменты** (только чтение): `get_company_profile`, `search_bank_analytics`, вызов модели.
3. **Сохранение контекста**: профиль, новость и найденные фрагменты передаются в каждый запрос к модели, вопрос пользователя (`/api/ask`) использует тот же контекст.
4. **Повтор при нехватке данных**: если найдено меньше 2 фрагментов аналитики, поиск повторяется с расширенным запросом (заголовок + отрасль и продукты компании). Если фрагментов нет совсем, все выводы помечаются как оценка ИИ.
5. **Самопроверка**: проверяется формат, источники и числа. При ошибке модель получает описание проблемы и отвечает заново (до 2 попыток). Если остались числа без подтверждения, делается одно исправление, и берётся только более чистый вариант.

Ответ содержит поле `trace` со всеми шагами, чтобы в интерфейсе можно было показать, как получен вывод.

## Переменные окружения
| Переменная | Обязательна | Значение по умолчанию |
|-----------|-------------|-----------------------|
| `LLM_API_KEY` | да | нет |
| `LLM_API_URL` | нет | `https://changellenge.up.railway.app/v1` |
| `LLM_MODEL` | нет | `qwen/qwen3.6-35b-a3b` |
| `LLM_TIMEOUT` | нет | `60` (секунд) |
| `AUDIT_LOG_PATH` | нет | `logs/audit.jsonl` |

Ключ нельзя хранить в коде и в репозитории: только в переменной окружения.

PowerShell: `$env:LLM_API_KEY="sk-..."`
Linux/macOS: `export LLM_API_KEY="sk-..."`

## Запуск
1. `pip install -r requirements.txt`
2. Задать `LLM_API_KEY` (см. выше).
3. Проверка сквозного сценария: `python test_pipeline.py` (или `python test_pipeline.py nlmk`).
4. API (после подключения `api_routes` в `main.py`: `app.include_router(router)`):
   `uvicorn main:app --reload`, документация адресов на `/docs`.

### Тесты
`py -m unittest discover -s tests -v` (без ключа и интернета).

### Docker
```
docker build -t alfa-news .
docker run -p 8000:8000 -e LLM_API_KEY=sk-... alfa-news
```

### Зафиксировать версии библиотек
В чистом окружении: `py -m venv venv`, `venv\Scripts\activate`, `pip install -r requirements.txt`, `pip freeze > requirements.lock.txt`.

Доступные компании: `polyus`, `rusgidro`, `severstal`, `nlmk`, `mmk`.

## Формат ответа LLM
```json
{
  "what_happened": "...",
  "why_important": "...",
  "risks": [{"text": "...", "basis": "bank_analytics | ai_estimate", "chunk_ids": [1]}],
  "opportunities": [{"text": "...", "basis": "bank_analytics | ai_estimate", "chunk_ids": []}],
  "actions": ["..."],
  "bank_view": "...",
  "uncertainty": "..."
}
```
`basis` показывает, на чём основан вывод: на аналитике Альфа-Банка (с номерами фрагментов) или на оценке ИИ.
Список источников в итоговом результате собирается кодом из реально найденных данных, а не из текста модели.

## Проверка ответа модели
- Ответ должен быть корректным JSON со всеми обязательными полями.
- Ссылки на `chunk_id` должны относиться только к реально переданным фрагментам.
- Вывод «по аналитике банка» без ссылки на фрагмент отклоняется.
- Числа, которых нет во входных данных, попадают в предупреждения.
- При ошибке проверки модели отправляется повторный запрос с описанием ошибки.

## Используемые модели
Используются только модели из списка организаторов кейса: `google/gemma-4-26b-a4b-it`, `z-ai/glm-5.3-flash`, `qwen/qwen3.6-35b-a3b`, `deepseek/deepseek-v4.1-flash`, `qwen/qwen3-vl-30b-a3b-instruct`, `moonshotai/kimi-k2.6`. Дневной бюджет ключа общий для команды (500 руб.).

## Безопасность и трассируемость
- Ключ API хранится в переменных окружения сервера и не передаётся в браузер; в журнале и сообщениях об ошибках он маскируется.
- Профиль компании содержит только обезличенные данные.
- Ограничены таймаут и число повторов запросов к модели; самопроверка делает не более одного дополнительного запроса.
- Доступ к инструментам разграничен: у агента есть только чтение (профиль, поиск аналитики, запрос к модели). Записи, удаления, запуска команд и произвольных адресов нет; неразрешённый инструмент отклоняется и записывается в журнал (`audit_log.ALLOWED_TOOLS`).
- Журнал `logs/audit.jsonl` фиксирует план, вызовы инструментов, обращения к модели (модель, длительность, размер, статус), результаты самопроверки и решения агента. Полные тексты запросов и ответов не пишутся.
- В источниках выводов отделены: «аналитика Альфа-Банка» (`basis: bank_analytics`, с номером фрагмента) и «оценка ИИ» (`basis: ai_estimate`).

# Ограничения
- Модель может ошибаться в интерпретации, поэтому все важные выводы нужно сверять с указанными источниками.
- Проект не является инвестиционной рекомендацией.
